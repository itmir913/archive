## 수업에서 부족했던 것

나는 중·고등학교에서 정보와 인공지능을 담당한다. 기계학습 단원의 수행평가로 "기계학습
모델 구현 보고서" 학습지를 사용한다. 45분 한 차시, 20점, 오픈북이다. 학생은 데이터를
선택하고 모델을 학습시킨 뒤 결과를 해석해 보고서를 제출한다.

이 45분을 티처블머신, 구글 코랩, 오렌지3로 각각 진행해 보았다. 세 도구 모두 본래 용도로는
충분히 동작한다. 문제는 내가 평가해야 하는 대상이 모델이 아니라 과정이라는 점이었다.

수행평가에서 내가 확인해야 하는 것은 다음과 같다. 어떤 데이터를 선택했고, 무엇을
예측하려 했고, 어떤 전처리를 적용했고, 어떤 모델을 어떤 근거로 선택했고, 점수가 그렇게
나온 이유를 어떻게 해석했는지. 그리고 이 항목들이 하나의 제출물로 묶여야 하고, 내가
다시 열어 확인할 수 있어야 한다.

세 도구에서는 이 부분을 학생이 따로 만들어야 했다. 화면을 캡처해 문서에 붙이고
설정값은 기억에 의존해 기재한다. 모델은 제출물에 포함되지 않는다. 채점할 때 내가
확인할 수 있는 것은 학생이 옮겨 적은 숫자뿐이고, 그 숫자를 재현할 방법은 없다.

한 차시라는 제약도 컸다. 컴퓨터실 PC는 전원을 끄면 디스크가 초기화된다. 로그인이 필요한
도구는 계정 문제로 첫 10분을 소비하고, 설치가 필요한 도구는 해당 학교 컴퓨터실의 상태에
따라 결과가 달라진다.

## 기존 도구를 계속 사용하는 방안

내가 먼저 검토한 것은 만들지 않는 쪽이다. 부족한 것이 제출물 하나라면 학습지 양식을 개선해
학생이 직접 기재하도록 하면 된다. 지금까지 그렇게 운영해 왔다.

이 방안을 접은 이유는 학생의 시간이 도구가 아니라 옮겨 적는 일에 들어가기 때문이다. 45분 중 상당 부분이 화면을 캡처하고 숫자를 옮기는 데 들어간다. 그 시간은
기계학습을 학습하는 시간이 아니다. 그리고 옮겨 적은 숫자는 검증할 수 없다. 학생이 실수로
잘못 적었는지 일부러 고쳐 적었는지 나는 구별하지 못한다.

두 번째로 검토한 것은 오렌지3 방식, 즉 워크플로 노드 편집기를 웹으로 이식하는 방안이다.
이건 명시적으로 범위 밖에 뒀다. 노드를 연결하는 조작 자체가 학습 대상이 되는데,
45분 안에 그 학습 비용을 부담할 수 없다. 대신 화면을 단계로 고정했다. 데이터, 전처리,
학습, 결과, 예측, 포트폴리오 순서로 진행한다.

세 번째는 서버를 둔 웹 애플리케이션이다. 이 검토는 분량이 많아서
[제약 둘](../two-constraints/)로 분리했다. 결론만 적으면, 전국
단위로 확산되면 어떤 계산으로도 부하를 감당할 수 없고, 이를 제한하려고 계정을 도입하면
학생 개인정보를 수집하게 되며, 수행평가 도중 서버가 정지하면 그 실패의 책임은 교사가
부담한다.

## 무엇을 만들기로 했나

두 가지로 정리했다.

첫째, 브라우저가 전부다. 공개하는 것은 GitHub Pages 정적 페이지 하나다. 데이터 업로드,
학습, 예측, 저장이 모두 학생의 기기에서 완결된다. 설치와 로그인이 없고 학생 데이터가
외부로 전송되지 않는다. 학교 PC든 가정 PC든 휴대폰이든 같은 주소를 열면 된다.

둘째, 하나의 프로젝트가 하나의 파일이다. `.mlpx` 파일 하나가 프로젝트이자 수행평가
제출물이자 포트폴리오다. 데이터, 설정, 학습된 모델, 지표, 학생이 작성한 글이 모두 그
안에 포함된다. 교사가 그 파일 하나를 열면 재학습 없이 학생이 확인한 내용을 그대로
확인할 수 있다.

```
새 프로젝트 → 데이터 준비 → 모델 학습 → 결과 분석 → 포트폴리오 작성 → 프로젝트 저장
```

## 기술 스택

| 레이어 | 기술 | 선택 이유 |
|---|---|---|
| 프런트엔드 | Vue 3 (`script setup`) + TypeScript strict | 화면이 단계로 구분되고 상태가 프로젝트 하나에 귀속된다 |
| 스타일 | Tailwind CSS | 임의 값 사용을 금지하고 최소 글자 크기를 `text-base`로 고정 |
| 상태 | Pinia | 컴포넌트가 저장소를 경유하도록 강제 |
| 다국어 | vue-i18n | en/ko 지원, ja는 추후 추가 |
| 저장 | IndexedDB + zip(`fflate`) | 자동 저장은 브라우저, 제출은 파일 |
| 검증 | zod | 외부 `.mlpx`를 읽을 때 런타임에서 차단 |
| 빌드·배포 | Vite + GitHub Pages | 정적 산출물 하나 |
| 백엔드(선택) | Python 3.12 + FastAPI + scikit-learn | 도커로 학교가 직접 구동. 없어도 전체 기능이 동작한다 |

학습 엔진은 두 가지다. 순수 JavaScript가 기본이고, scikit-learn을 WebAssembly로
컴파일한 Pyodide가 학생이 선택하는 옵션이다. 같은 화면에서 둘을 비교할 수 있다.
Pyodide는 26.3MB에 초기화가 15.4초 소요되어 기본값으로 채택할 수 없었다.

현재 지원 범위는 다음과 같다.

- 데이터: 표(`.csv`, `.xlsx`)와 이미지
- 과제 유형: 분류, 회귀, 군집
- 알고리즘 8종: 결정트리, 랜덤포레스트, 로지스틱 회귀, KNN, 나이브 베이즈, SVM,
  선형 회귀, K-평균
- 모델 직렬화 형식 7종. 학습된 모델이 파일 내부에 저장된다

`randomState`는 항상 저장하고 항상 사용한다. 점수가 움직였다면 설정이 움직인 것이다.
재현 가능성이 확보되지 않으면 교육용 도구로 사용할 수 없다.
