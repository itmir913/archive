## 경고만 발생하고 넘어간다

사용 중이던 아이콘 패키지가 deprecated 상태가 되었다. 이름이 변경되었을 뿐 peer 요구사항은 그대로여서 교체 자체는 간단해 보였다.

문제는 검증 방법이다. Vue는 등록되지 않은 컴포넌트를 만나면 렌더 시점에 경고를 출력하고 넘어간다. 빌드는 성공하고 타입 검사도 통과한다. 아이콘 하나가 새 패키지에 존재하지 않아도, 그 화면을 직접 열기 전까지 아무도 인지하지 못한다.

아이콘은 수십 종이 수십 개 파일에 분산되어 있다. 육안 확인은 방법이 되지 못한다.

## 교체보다 테스트를 먼저

패키지를 교체하기 전에 테스트를 작성했다. 소스를 스캔해 사용 중인 아이콘 이름을 수집하고, 그 이름이 패키지에 전부 존재하는지 확인하는 방식이다.

그 테스트가 즉시 하나를 발견했다. 새 패키지에 GitHub 아이콘이 없다. 상표 문제로 브랜드 아이콘 전체가 제거되었기 때문이다. 교체를 먼저 진행했다면 개발자 정보 화면을 열기 전까지 발견하지 못했을 것이다.

해당 버튼은 소스 코드를 가리키므로 코드 아이콘으로 교체했다. 이름이 변경되었다고 추측한 몇 개는 별칭이 유지되어 그대로 동작한다는 사실도 테스트가 확인했다. 추측으로 일괄 치환했다면 불필요한 변경이 발생했을 것이다.

## 테스트가 확인하는 세 가지

첫째, 스캔이 실제로 아이콘을 발견하는지 확인한다. 정규식이 손상되면 빈 목록을 순회하며 조용히 통과한다. [검증 대상이 없는 테스트](../audit-as-release-gate/)는 통과가 의미를 가지지 않는다.

둘째, 전부 같은 패키지에서 임포트하는지 확인한다. 교체가 중단된 상태면 두 패키지가 번들에 공존하고, 옛 것을 삭제하는 순간 해당 파일들이 손상된다.

셋째, 사용하는 이름이 패키지에 모두 존재하는지 확인한다. 원래 목적이 이것이다.

경로 처리에서 한 가지 주의점이 있었다. CI는 우분투이고 로컬은 윈도우다. 드라이브 문자를 수동으로 처리하면 플랫폼마다 결과가 갈라지므로, 표준 변환 함수를 사용한다.

## 함께 기록한 것

이 작업 중에 의존성 경고 두 건을 확인했다. 도달하지 않는 경로라서 조치하지 않기로 판단했는데, 근거와 함께 ROADMAP에 기록했다.

기록하지 않으면 다음에 누군가 자동 수정을 실행한다. 이 경우 자동 수정이 제안하는 조치는 메이저 버전 다운그레이드이므로, 경고를 제거하려다 기능을 잃는다. 조치하지 않은 항목일수록 판단 근거를 남겨야 한다.
