## 첫 실행에만 동작하던 초기값

기본 치환 규칙과 기본 유의어는 프로젝트 파일을 새로 생성할 때 테이블에 삽입된다. 초기 구현은 `seed_default_*`라는 이름 그대로였다. 테이블이 비어 있을 때만 동작하고, 한 번 채워지면 다시 실행되지 않는다.

이 구조의 결함은 기본값을 확충하는 순간 드러났다. 반복 문장부호나 비가시 문자 규칙을 새로 추가해도, 이미 프로젝트 파일을 만들어 사용 중인 교사에게는 전달되지 않는다. 그 사람이 새 규칙을 받으려면 프로젝트를 새로 생성해야 하는데, 학기 중에 작성하던 파일을 포기하라는 요구는 성립하지 않는다.

기본값은 앱이 제공하는 기능의 일부다. 앱을 업데이트했는데 기능이 갱신되지 않는다면 업데이트의 의미가 약해진다.

## 자동 병합을 선택하지 않은 이유

가장 단순한 해법은 파일을 열 때마다 누락된 기본값을 자동으로 병합하는 것이다. 사용자는 아무것도 하지 않아도 최신 규칙을 보유하게 된다.

그런데 치환 규칙은 사용자가 직접 수정하는 대상이다. 기본으로 제공한 규칙을 자기 학교 관행에 맞춰 변경하거나 비활성화한 사람이 있고, 그 판단은 존중되어야 한다. 자동 병합은 "내가 지운 규칙이 왜 다시 나타나는가"라는 상황을 만든다. 파일을 열 때마다 조용히 데이터가 변경되는 동작은 이 앱이 회피해 온 종류의 동작이기도 하다.

결국 갱신 여부를 사용자가 결정하도록 했다. `seed_default_*`를 `apply_default_*`로 변경해 누락분만 병합하는 동작으로 만들고, 실행 시점은 사용자가 버튼을 누른 때로 한정했다.

## 갱신이 필요하다는 사실을 알리는 방법

버튼을 제공하는 것만으로는 부족하다. 설정 화면에 들어가 버튼을 발견해야 갱신이 이루어지므로, 대부분의 사용자는 버튼의 존재조차 인지하지 못한다.

기본값 목록에 버전을 부여하고 `APP_CONFIGS`에 적용된 버전을 기록했다. 앱이 보유한 버전이 파일에 기록된 버전보다 높으면 갱신이 필요한 상태이며, 이때 버튼에 알림 점 배지가 표시된다. 처음에는 pulse 애니메이션과 링으로 강조했는데, 설정 화면에서 계속 움직이는 요소는 시선을 과도하게 소모한다. 정적인 배지로 교체했다.

`APP_CONFIGS`는 이후 다른 상태에도 활용했다. 기록 화면 툴바의 여섯 개 토글(틀고정, 스마트스크롤, 셀 높이, 빈 학생 강조, 미리보기, 개인정보 접기)은 매번 기본값으로 초기화되어, 같은 설정을 반복해서 조정해야 했다. 이 값들도 파일에 저장해 진입 시 복원한다. 다만 조회는 `get_configs`로 요청한 키만 반환하도록 구현했다. 이 테이블에는 암호화 salt와 검증 토큰이 함께 존재하므로 전체를 프론트엔드로 전달하면 안 된다.

## 연쇄 치환이라는 부작용

기본 규칙을 확충하면서 예상하지 못한 문제가 발생했다. 괄호류를 정리하는 규칙이 `【】`를 `<`와 `>`로 변환했는데, 규칙 목록의 뒤쪽에 `<`와 `>`를 작은따옴표로 변환하는 규칙이 존재했다. 두 규칙이 순차 적용되면서 중간 결과가 다시 치환 대상이 되었다.

치환 엔진에 중간 결과 보호 장치를 추가하는 방향도 검토했으나, 규칙 간 의존 관계를 엔진이 추론하게 만드는 일은 규칙이 늘어날수록 예측 불가능해진다. 기본 규칙이 최종값을 직접 지정하도록 수정하는 편이 확실했다. `【】`는 처음부터 작은따옴표로 변환한다.

개수가 가변적인 패턴(마침표 반복, 느낌표 반복)은 리터럴 치환으로 표현할 수 없으므로 정규식 규칙으로 추가했다. NBSP나 ZWSP 같은 비가시 문자도 문자 클래스로 표기해, 목록에서 "정규식" 배지로 구분되도록 했다. 눈에 보이지 않는 문자를 규칙 목록에서 확인할 방법이 그것 외에는 없었다.
